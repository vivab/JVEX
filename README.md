# JVEX AI

**JVEX** — проект публичного ИИ с единым интерфейсом, несколькими API-провайдерами, переключением моделей, интернет-поиском и режимом **JVEX Code**.

Сайт и будущий APK используют один интерфейс. GitHub Pages размещает **только веб-клиент**, API и лимиты работают отдельно через Cloudflare Worker. Замена Cloudflare на другую серверную платформу возможна.

## Реализовано в коде

- Мобильный бело-зелёный интерфейс, чаты, история на устройстве, экспорт, тёмная тема и изменение основного цвета.
- Отправка фото, голосовой ввод через поддерживаемый браузер.
- Markdown отображается как форматированный текст (без видимых двойных звёздочек). Название модели не показывается под ответом.
- Ответ появляется **постепенно** после получения результата от модели; в ожидании показываются «Читаю…», «Думаю…» и тематические статусы вроде «Пишу код для игры…». Строки «Этапы работы» описывают общие операции, а не скрытую цепочку рассуждений нейросети. Это визуальная анимация вывода, а не настоящее токеновое потоковое API. Учитывается настройка уменьшения движения в браузере.
- Перед отправкой показана **оценка стоимости задачи** в единицах Free. Сервер самостоятельно классифицирует запрос и атомарно списывает 1, 2 или 3 единицы из лимита. Простая беседа — 1; фото или большой вопрос — 2; Code: объяснение — 1, правка — 2, большой проект / целая игра — 3. Показанная цена предварительная, фактическая стоимость приходит от сервера. Если все модели завершились ошибкой, резервирование возвращается полностью; переключение между моделями не списывает дополнительные единицы.
- Кодовые блоки можно скачивать как настоящие текстовые файлы (`.html`, `.js`, `.py`, `.json` и другие); несколько файлов можно скачать одним ZIP. Для именования файла модель использует блок формата `язык file=путь/имя.ext`. Очень большие проекты нужно создавать по частям; генерация готовых бинарных DOCX/PDF/APK пока не поддерживается.
- Раздельный роутинг моделей: **обычный чат → Groq GPT-OSS 20B → Qwen 3.8 27B → GPT-OSS 120B**, **JVEX Code → Qwen 3.8 27B → GPT-OSS 120B → GPT-OSS 20B**. Можно вручную выбрать модель в настройках. При ошибках и ограничениях модель переключается с сохранением истории. Есть резерв OpenRouter, если настроен его ключ.
- **Gemini 3.8 Flash** поддерживается через `GEMINI_API_KEY` как дополнительный провайдер и предпочтительный вариант для фото при его наличии. Без установленного ключа Gemini не считается подключённой и не используется. Для добавления секретного ключа: GitHub → Settings → Secrets and variables → Actions → New repository secret → `GEMINI_API_KEY`. Ключ нельзя добавлять в файлы сайта, README или чат. Бесплатность и лимиты Gemini зависят от тарифа, модели и региона.
- Необязательный Tavily Search и Gemini Google Search Grounding. Источники показаны, если поиск действительно вернул их.
- JVEX Code **читает публичные GitHub-репозитории и помогает с кодом**, но пока не может коммитить, запускать тесты или создавать PR за пользователя.
- Пять тарифов в меню. **Без регистрации и оплаты включён только Free**, остальные отключены.

## Тарифы (проектные значения, без утверждённых цен)

| Тариф | Чат | JVEX Code |
| --- | ---: | ---: |
| JVEX Free | 60 / сутки | 10 / 5 часов |
| JVEX Plus | 100 / сутки | 20 / 5 часов |
| JVEX Pro | 300 / сутки | 60 / 5 часов |
| JVEX Premium | 1000 / сутки | 250 / 5 часов |
| JVEX Code | 40 / сутки | 200 / 5 часов |

**Числа в таблице — доступные единицы лимита, не гарантированное количество отдельных сообщений:** одна сложная задача может использовать несколько единиц. Например, 10 единиц Code/5ч = до 10 простых задач или 3 больших задачи по 3 единицы и 1 простая. До отправки стоимость видна в чате.

На данном этапе **только Free** имеет серверные лимиты. Code Free: пятчасовой период начинается **при первом запросе** и обновляется ровно спустя пять часов; обычный чат: 00:00 UTC. Лимиты считаются **на сервере**, а не в браузере. Без регистрации используется хеш IP: это не полноценный способ идентификации, разные люди за одним адресом могут разделять лимит.

Глобальная защита для бесплатных API по умолчанию: максимум 600 запросов чата/сутки, 150 запросов Code/сутки на весь проект и 4 запроса в минуту для анонимного посетителя. Эти пределы можно изменить в wrangler.toml; они предназначены для предварительной беты и не гарантируют защиту от атак. Для большого публичного сервиса нужны авторизация, антибот-защита и мониторинг расходов.

## API (бесплатная серверная часть)

GitHub Pages и APK сами по себе **не защищают общие API-ключи**. Поэтому Worker держит ключи в Secrets и обеспечивает серверные лимиты в SQLite Durable Object.

### Подключение прямо с телефона

Создайте аккаунт Cloudflare Workers и API-токен с правами Workers. В GitHub → Settings → Secrets and variables → Actions → New repository secret добавьте:

| Секрет | Назначение |
| --- | --- |
| CLOUDFLARE_API_TOKEN | Cloudflare API token |
| CLOUDFLARE_ACCOUNT_ID | Необязательно: Account ID уже задан в GitHub workflow |
| QUOTA_SALT | Необязательно: если отсутствует, серверный salt безопасно и стабильно выводится из секретного токена Cloudflare; при замене токена счётчики анонимных пользователей могут сброситься |
| GROQ_API_KEY | Необязательный ключ Groq |
| OPENROUTER_API_KEY | Необязательный ключ OpenRouter |
| GEMINI_API_KEY | Необязательный ключ Gemini |
| TAVILY_API_KEY | Необязательный ключ Tavily |

Сейчас достаточно **CLOUDFLARE_API_TOKEN** и **GROQ_API_KEY**. Account ID уже задан в workflow, а соль лимитов создаётся автоматически при первом деплое. Не вставляйте API-ключи в исходники или в чат.

Для последующих обновлений: GitHub → Actions → **Deploy JVEX API (manual)** → Run workflow. Workflow проверяет API и лимиты, разворачивает Worker и запускает тест живого чата. Адрес API уже встроен в веб-интерфейс; посетителям не нужно ничего вводить.

Модели по умолчанию (могут перестать быть доступны по API):
- GROQ_MODEL: openai/gpt-oss-120b
- GROQ_VISION_MODEL: qwen/qwen3.8-27b
- OPENROUTER_MODEL: openrouter/free
- GEMINI_MODEL: gemini-2.5-flash

Стоимость, доступность конкретной модели, бесплатные лимиты и разрешение на публичную интеграцию нужно проверять у провайдеров. В реальном публичном проекте нельзя обещать безлимитную работу только за счёт бесплатных API.

## Компоненты

- index.html — клиентский интерфейс.
- worker/src/index.js — API proxy, fallback, поиск, фото, GitHub.
- worker/src/quotas.js — серверные анонимные квоты и 5-часовой Code reset.
- worker/wrangler.toml — Worker + Durable Object SQLite.
- worker/test/index.test.js — тесты API и квот.
- .github/workflows/pages.yml — проверка и GitHub Pages.
- .github/workflows/deploy-worker.yml — ручное развёртывание Worker.

## Ограничения и безопасность

- Сейчас не реализованы настоящие подписки, платежи, вход в аккаунт, синхронизация чатов между устройствами, Android APK и запись в GitHub кодовым агентом.
- Для действий от лица пользователя в GitHub понадобится GitHub OAuth/App, изолированный runner, согласие на запись, просмотр diff и PR.
- Сообщения, фото и фрагменты GitHub-кода будут передаваться внешним ИИ-провайдерам; поиск передаёт запросы поисковой системе. У каждого провайдера свои условия обработки данных.
- История хранится только в localStorage; очистка данных браузера её удаляет. Для публичного релиза понадобится надёжное хранилище.
- API-ключи не должны появляться в APK, GitHub Pages или исходном репозитории.
